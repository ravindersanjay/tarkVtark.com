How to configure for Supabase
Set environment variables (examples):
SPRING_DATASOURCE_URL=jdbc:postgresql://db.<project>.supabase.co:5432/postgres?sslmode=require</project>
SPRING_DATASOURCE_USERNAME=<db_user>
SPRING_DATASOURCE_PASSWORD=<db_password>
FILE_PROVIDER=supabase
SUPABASE_URL=https://<project>.supabase.co</project>
SUPABASE_SERVICE_ROLE_KEY=<your_service_role_key> (server-side secret!)
SUPABASE_STORAGE_BUCKET=attachments
If your bucket is private and you want downloads to work, you can:
Keep storing the public URL only for public buckets.
Or store the object path and expose a signed URL endpoint (Supabase supports signed URLs or you can proxy through the backend).
Notes and caveats
The implementation sends the whole file in memory to build the multipart body. For very large files you may want to stream the upload (use streaming multipart or S3 approach).
The upload returns a public URL assuming the bucket is public. If the bucket is private, you should store the path (not a public URL) and generate signed URLs for clients when needed.
The Supabase service_role key must remain server-side only — never expose to the browser.
